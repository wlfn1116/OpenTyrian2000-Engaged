### Commit messages (two — the fix is separate from the test that found it)

**Commit 1 — the product fix**

```
stop the online save checkpoint destroying the peer's quit notice, and bound it

network_shop_sync_for_save consumed whatever was at the head of the reliable
queue to reach the acknowledgement behind it. A PACKET_GAME_QUIT is acknowledged
on arrival, so the peer counts it delivered and never repeats it: consumed here,
the quit handler never learns the peer left. It is now left for its own waiter.

The loop also had no deadline and no liveness check, so a peer that vanished
between the request and the reply held the game in it with no way out. It is now
bounded by NET_SHOP_SAVE_WAIT and by network_peer_alive.

A debug block queued ahead of the acknowledgement was dropped rather than
adopted, losing the peer's debug edit on this machine alone. network_debug_sync_pump
only inspects the head, so every wait has to pair it with network_shop_pump;
this one did not.
```

**Commit 2 — the tests and instrumentation**

```
say where a wire test stopped, and pin the debug block's contents

A stalled wire scenario reported only that the peers never finished. Failures now
print the phase entered, the phase the peer reached, reliable-queue depth and head
type, acknowledgement state and backlog, packets acknowledged into a full window,
peer liveness and ping. That is enough to tell a starved wait from one wedged
behind a head nobody claims, which is the difference between a minute and an hour.

network_test_peer gains a wall-clock ceiling inside the harness's own patience, so
a wedged peer prints why it stopped instead of being killed with its output unread.

The debug-menu wire block is now pinned in qa_online.c: pack, mutate every field,
adopt, and re-pack to compare the whole block. That catches a field the debug menu
edits and the block does not carry, which is otherwise only visible as the two
machines quietly simulating different games. Hostile difficulty, noclip, autofire
and twiddle bytes are checked to be clamped rather than indexed with.
```

## 4. Bugs found

**1. `network_shop_sync_for_save` destroys reliable packets belonging to other subsystems.**
It called `network_update()` on any head it did not recognize. That head was already acknowledged
on arrival, so the sender counts it delivered and never repeats it — it is gone. For a player: if
your partner quits while you are saving at the outpost, the quit notice can be eaten and your
machine never learns they left. Fixed (commit 1). Measured, not theorised: with the wire scenario
that exposed it, this alone accounted for half the failures (17/25 → 9/25).

**2. `network_shop_sync_for_save` could hang the game forever.** `while (!network_shop_save_ready)`
with no deadline and no liveness re-check. A partner who vanishes between the save request and the
reply leaves you in that loop permanently — no timeout, no escape. Fixed (commit 1).

**3. A debug block queued ahead of the save acknowledgement was dropped, not adopted.** Your
partner's debug-menu edit silently fails to apply on your machine while applying on theirs. Fixed
(commit 1). The prompt's claim that `network_debug_sync_pump` is "untestable as written" is
narrower than stated: every other caller already pairs it with `network_shop_pump`, which is the
correct idiom given the ordered queue. This was the one caller that did not.

**4. Wire-scenario barriers do not scale past about two.** Not a product bug — a limit in
`qa_net.c`'s test harness, and it is the reason Phase 2 cannot be built yet. A six-barrier phase
failed roughly **1 run in 4**, with a peer stalled on an announcement that never arrived,
`network_acked_dropped` at zero, and a **hole at the head of the receive window** (`depth 2, head
type 0000`) that did not heal in twelve seconds. So the packet was neither dropped into a full
window nor retransmitted. Unexplained. Written up in `doc/notes.md` with the two suspects
(`network_check` retries only `packet_out[0]`; `network_send` resets `last_out_tick` only while
`network_is_sync()`, and a barrier waiter is silent for long stretches).

**5. Test-environment gap:** the wire test peer never initializes `player[].lives`, which is a
pointer the game sets at new-game time. Any code path reaching `arcade_armor_max` faults on it —
`JE_getShipInfo` at `varz.c:481`, reached through any debug-block adopt. Fixed in `qa_net.c`.
